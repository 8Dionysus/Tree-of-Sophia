# `tos-command` laboratory coordinator

CMD.1 exercises the candidate commit protocol with synthetic records and a dedicated PostgreSQL database. It is not a ToS source writer, admission validator, rights service, or byte store. `SyntheticByteRef` carries a digest and length for transaction tests; it proves no file durability. External owner authorization is deliberately refused. General ToS rules remain `FullOnly` until owner-approved coverage exists.

`PgCoordinator::commit` uses a short `READ COMMITTED` transaction. Its first data read locks the domain sequencer row; subsequent exact/predicate/current-rights checks, compound record writes, receipt, ordered log, outbox and sequence update commit together. The adapter records client-observed lock wait/hold/transaction times. `read_cut` captures a `REPEATABLE READ` MVCC cut, while `seal_cut` checks its contiguous immutable log prefix. The laboratory publication digest is a log digest only; it is not an STO membership/history/index root or a VAL publication seal.

The synthetic current record pointer and per-version history rows are written in the same transaction. `read_record_version` gates even predecessor reads on current local rights. Each command log member commits to its exact namespace, key, version, synthetic digest and length; `read_cut` and `seal_cut` compare every history row with those members, including count and orphan checks. The log has no external trust anchor, and historical rows do not establish STO custody or an actual byte locator. The laboratory member format has no migration route for older lab data.

The typed predicate token includes owner, scope, definition version and generation. Synthetic writes must name their invalidations. This lab checks that named tokens exist and are complete; it cannot prove that an owner enumerated every dependency. No source kind names are hardcoded. `FullOnly` candidates bind `full_base_seq`; a changed base returns conflict for re-audit outside the lock. Current local rights and read gates share the sequencer/row lock. Rule and contract digest updates emit ordered events. Job fence epochs cannot decrease, and commits lock their job row before verifying the epoch.

`synthetic_delta_digest` binds the exact laboratory write list and named invalidations, and the commit refuses a candidate whose delta digest or preparation digest differs. It is deliberately separate from FND's source command input profile. The integration fixtures use a synthetic raw request digest; they do not claim compatibility with a legacy request serializer.

The lab caps one command at 64 writes, 1,024 reads and 1,024 invalidations per write. Its in-memory cut builder stops at 100,000 log events; it is a bounded protocol fixture, not a production publication algorithm. A production publisher needs streamed or partitioned roots and measured target-scale capacity.

To run the integration tests, provide `TOS_CMD_POSTGRES_URL` for a dedicated ephemeral PostgreSQL instance and execute `cargo test -p tos-command --test postgres_lab --locked -- --nocapture` from the OPS-integrated workspace. The tests are inert without that variable; a CI lane must set it and assert the test count rather than relying on a skipped green. The lab schema uses only `cmd1_*` tables, and tests use unique synthetic domains. No test reads `ToS/` or opens a live corpus locator.

Before any writer cutover: replace synthetic byte markers with STO durable locators and cold restore proof; replace lab attestation inputs with VAL's frozen ABI and actual rule results; adopt an owner-approved command/receipt byte profile; enforce DB writer privileges for all mutators; prove owner-declared invalidation coverage and current external authority fencing; seal exact membership/history/index roots; test backup/restore and selected software/data rollback. PostgreSQL topology and throughput remain root ARC.1/CAP.1 decisions.
