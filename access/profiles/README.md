# Access profiles

The [standalone profile](standalone.v1.json) selects product components and runtime posture. The [deployment profile](deployment-profile.default.v1.json) records resource values under the [versioned contract](../contracts/deployment-profile.v1.schema.json). Each field description specifies its unit. Missing fields inherit the built-in profile. A null value requires an explicit value at the operation that needs it.

Select a deployment profile with `--profile PATH` or `TOS_DEPLOYMENT_PROFILE`; the flag takes precedence. The executable uses the embedded default when neither is set. The installer reads the four `archive_install` fields, and its four `--max-*` flags override the selected values. The built-in limits use four times the measured software archive values, rounded up to powers of two; the contract records the measurement. Select limits appropriate to the admitted archive. Build, verify, and extract retain their explicit limits. `tos bridge` reads the eight `bridge` fields. They were set from the bridge's measured run with the army simulator (500 agents over 200 concurrent clients, 2·10⁵ acts; interface plan, «Замеры В4»): 256 connections carry the 200 clients and the page; a 4 MiB request body carries the largest act batch; a window of 1,000 records is the journal's own query limit. Agents' tickets and proposals slow from 200 open proposals and wait at 2,000, after the review screen, which shows 50 groups at a time; a person who reviews faster raises them in their own profile. The remaining profile fields describe current defaults and will be connected to their boundaries in later packages.
