## Context

The Operator selected a complete Rust migration for the maintained executable
foundation of Tree of Sophia and approved its implementation plan. The growth
horizon comprises billions of source records and hundreds of concurrent agent
clients. Source history, rights, competent assessment and reviewed admission
retain their distinct owners throughout that growth.

The current foundation spans source commands and validators, Python builders
and access runtime, browser and Worker rules, release tooling and integration
exports. TOS-D-0059 already establishes partitioned derived carriers and
explicit query compilation. TOS-D-0062 separates software, corpus and
integration releases. Those boundaries supply the starting point for the
language and storage transition.

## Decision

Move all maintained ToS-owned executable rules and tools to Rust. Shared
libraries carry exact codecs, identity and version types, schema and operation
descriptors, source validation, compilation and query behavior. Native and
WASM profiles share the relevant domain implementation. Host adapters supply
platform I/O, authentication framing and presentation through explicit
interfaces.

Maintain a reviewed disposition for every active executable surface, including
research tools, CI command bodies, packaging and exporters. Each receives a
Rust replacement, a bounded platform/presentation role, a data role, or an
evidence-backed retirement. Historical builder bytes remain exact retained
inputs under their existing provenance contract. Authored text, source bytes,
schemas and external products keep their appropriate representations.

Build extensibility around source-owned versioned registries and contracts.
Stable IDs preserve their spelling and identity independently of filesystem
placement or backend. Domain kinds, predicates, rights and review effects
come from their owning definitions. Operational limits and supported behavior
are explicit profile data with validation and measured resource bounds.

## Architecture and preserved invariants

- Source storage preserves immutable bytes, stable identities, metadata
  revisions, historical locators, fixity and custody. Bounded segments and
  reusable manifests support growth; versioned indexes support selective reads.
- Validation declares its exact inputs and dependency scopes. Global checks
  remain explicit operations; affected checks require complete dependency
  coverage for their stated rules.
- Commands bind current authorization and versions to an atomic result,
  durable receipt and publication handoff. Retry, cancellation, lost response,
  concurrent conflict and recovery have specified outcomes. Each write scope
  has an explicit writer authority.
- Compilers publish one identified source snapshot and its compatible read
  artifacts. Queries declare coverage, budgets and continuation state.
- Current access policy is evaluated under the selected online or offline
  profile. Historical selection preserves exact evidence and the applicable
  authority contract. Byte deduplication preserves independent record rights;
  an allowed record export includes only permitted bytes.
- Software, data and downstream integration retain independent release
  identities and compatibility rules. Source assessment, rights, canon and
  public activation continue through their actual owner routes.

## Transition and acceptance

Establish exact consumer contracts, representative independent fixtures and
an installable Rust reader before replacing larger runtime families. Pin each
codec profile explicitly, including duplicate-key behavior, number handling,
Unicode, text coordinates, canonical bytes and error envelopes. A partial
implementation declares its supported profile and keeps the remaining
compatibility obligations open.

Directions can progress against accepted interfaces. Their delivery order
preserves data recoverability, existing consumer contracts and a clearly
selected implementation per operation. Transitional reference implementations
have explicit removal conditions.

Acceptance proceeds through source and contract conformance, installed
native/WASM behavior, concurrency and failure recovery, and a measured target
capacity profile. The profile identifies actual hardware, topology, data
shape, histories, skew, client mix and numerical service objectives. Target
capacity evidence precedes large cutover and final legacy retirement.

Data conversion is resumable and verifies exact membership, bytes, historical
references and locator mappings before a selected publication pointer changes.
Restoration exercises the compatible software/data pair and current policy.
Completion includes all maintained tools and consumers, final installed
artifacts, required CI, operational procedures and retirement evidence.

## Options Considered

- Restrict Rust to selected hot loops while maintaining the other current
  implementations. That scope was considered in earlier acceleration work;
  the approved decision now covers the complete maintained foundation.
- Introduce the complete migration through contract-preserving, independently
  verifiable increments. The Operator selected this route with delegated
  direction ownership and whole-system acceptance.

Backend and library choices remain implementation decisions with explicit
compatibility, recovery and capacity gates. The initial server coordinator
candidate is PostgreSQL; its selection depends on the owner review. Existing
SQLite and D1 serving profiles retain their own measured scope. ToS relies on
established coordination systems for distributed consensus.

## Rationale

One domain implementation reduces drift among tools, transports and execution
hosts. Rust supplies a common native/WASM implementation target and makes
resource and state boundaries available to types and explicit interfaces.
Selective storage, bounded execution and concurrent command protocols carry
the scaling requirements. Their behavior is demonstrated through measured
workloads and recovery cases.

## Consequences and continuity

- TOS-D-0038 retains standalone ToS access ownership and shared read semantics.
  This decision supersedes its specific Python core implementation choice as
  replacement consumers satisfy the transition contract.
- TOS-D-0059 retains partition integrity and explicit offline compilation.
- TOS-D-0062 retains independent software, corpus and integration releases,
  exact pair compatibility and the existing public-activation posture.
- TOS-D-0068 retains subject-first wording, exact historical inputs and
  source-owned descriptive text. Typed contracts carry mechanical conditions.
- Existing source, review, canon and sibling-owner authority remains with its
  corresponding owner. Migration evidence reports the exact operation checked.
