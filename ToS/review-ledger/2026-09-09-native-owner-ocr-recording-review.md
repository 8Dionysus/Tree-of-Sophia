## Owner boundary

The new `text-layer.record-owner-ocr` operation has its own protected
`tos_local_text_layer_record_owner_ocr_v1` grant and discoverable handler.
The existing `text-layer.record-ocr` remains supplied-only, with unobserved
provider execution. These operations cannot borrow each other's grants.

The laboratory owns actual Tesseract execution and signed execution receipts;
abyss-machine owns runtime artifacts, resource policy and exact admission.
ToS owns source reading, new-layer derivation, evidence recording and textual
assessment. Its bridge invokes only the fixed clean source-pinned owner
`verify` / `verify-record` modes, with no shell, signer credentials, runtime
launch, package installation, network or caller-selected program.

Separate current source-read, new-layer derivation and evidence-read grants
are required. Exact existing Item/File rights and newly scoped layer rights
precede payload or result reads. The copied receipt, signature and public key
are independently digest-bound; the owner verifier authenticates them and
closes exact source scope, language and output identity. Caller JSON cannot
assert an observed execution flag without this independent verification.

The immutable twelve-file packet retains the separate earlier execution and
later ToS annotation/recording relation. It creates no model invocation and
does not claim that ToS executed OCR. Prepare, commit, retry and retained
recovery reverify exact evidence but never repeat OCR. Native metadata reads
authenticate only copied metadata, without source or OCR text. Exact content
reads still need the separate explicit private access route.

The layer is raw OCR, version 1, unreviewed, with no inherited accepted use,
source fidelity, competence, publication or canon. The existing image-source
assessment route remains unsupported; its failure is intentional until a
separate source-visible image comparison contract exists. Historical reads
need the pinned owner verifier source, not an unexpired write/runtime grant.
