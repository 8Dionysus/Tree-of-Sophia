## Source, operation and limits

The existing source-bound assessment journal can now materialize one selected
freeform human form against its current exact source inputs and committed
assessment history. See the [owner command](../../mechanics/growth-cycle/parts/branch-growth-cycle/README.md#assessed-form-materialization)
and [human-form law](../doctrine/HUMAN_FORMS.md).

`materialize-form` is discovered by `describe` for a source-selected freeform
form. It requires the independently selected v2 owner configuration and the
expected subject/snapshot. It accepts no submitted grant, clock, assessment,
wording or scope override. The current form and every content dependency must
come from explicit source selections. The subject/form set must be adjacent
and exact, and whole-subject context is mandatory. Prior forms remain history,
not current target records. Linguistic context may be separately owner-bound;
putting a language declaration inside a submitted form does not authorize it.

The operation reads one committed journal head/history and evaluates the same
policy used by assessment commands. It does not append a review, call a model,
write a source or publish a graph. Ready wording requires current admission;
otherwise it returns an explicit state and no wording. The result's admission
is nullable when structural/context checks stop before policy application.
Its 64 KiB ceiling is not the public scene reader's smaller delivery budget.
